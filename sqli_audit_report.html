2. Vulnerable vs Secure Code Patterns (Side-by-Side Reference)

1. Multi-Tenant User & Entity Lookup by Email / Subdomain
❌ Vulnerable (Raw String Concatenation)
Directly concatenating user input allows SQL injection escape (e.g. ' OR 1=1 --):
# VULNERABLE PATTERN: query = f"SELECT * FROM users WHERE email = '{user_input}'" result = await db.execute(text(query))
✅ Secure (CoachGenie Implemented Pattern)
SQLAlchemy 2.0 AST compilation passes parameters to asyncpg as bound variables:
# COACHGENIE SECURE PATTERN: stmt = select(User).where( and_(User.tenant_id == tenant_id, User.email == email) ) result = await db.execute(stmt)
2. Dynamic Text Search / Filter Operations
❌ Vulnerable (Template Literal / Format String)
Embedding search keywords into raw LIKE clauses leads to syntax breaking & injection:
# VULNERABLE PATTERN: sql = f"SELECT * FROM students WHERE first_name LIKE '%{search}%'" await db.execute(text(sql))
✅ Secure (Parameterized ILIKE Pattern)
SQLAlchemy passes search pattern as bound data value, preventing query alteration:
# COACHGENIE SECURE PATTERN: safe_search = search.replace("%", "\\%").replace("_", "\\_") conditions.append(Student.first_name.ilike(f"%{safe_search}%")) stmt = select(Student).where(or_(*conditions))
3. Paginated Multi-Filter Queries with Sorting
❌ Vulnerable (Dynamic SQL Clause Assembly)
Building dynamic ORDER BY and LIMIT clauses with string concatenation:
# VULNERABLE PATTERN: query = f"SELECT * FROM leads ORDER BY {sort_col} LIMIT {limit} OFFSET {offset}" await db.execute(text(query))
✅ Secure (Safe ORM Pagination & Whitelisted Sorting)
Using typed column mappings and built-in pagination methods:
# COACHGENIE SECURE PATTERN: stmt = ( select(Lead) .where(Lead.tenant_id == tenant_id) .order_by(Lead.created_at.desc()) .offset((page - 1) * limit) .limit(limit) ) result = await db.execute(stmt)
